# Decisions

Newest first. Reasons marked (inferred) were not stated by the author.

- **2026-11-05: the API goes on AWS Lambda instead of Render.** The author chose Lambda for a low-traffic portfolio (no idle cost, no one-minute sleep). Express runs unchanged through the Lambda Web Adapter with a streaming Function URL; live metrics fall back to the 15-second refresh because Lambda cannot hold sockets. Render (`render.yaml`) stays as a fallback. Cloud Run and Rust were discussed and not chosen.
- **2026-11-05: refresh tokens and Remember me added.** The author asked for both after asking whether the single long-lived token was safe. Short access token (15m) plus a stored, rotating refresh token, both HttpOnly cookies, so logout and password changes really end a sign-in and a copied token is only good for minutes. Remember me only sets how long the sign-in lasts (30 days instead of one day or until the browser closes); refresh tokens work with or without it.
- **2026-11-05: hosting plan is the frontend on Vercel and the backend on Render now, a home server later (different domains).** So the cookie is made first-party by proxying `/api` through Next rewrites, not by `SameSite=None` (which Safari and some Chrome settings block). The chat stream and live-metrics socket go direct with a one-minute token. Alternatives that were offered: a shared parent domain (ruled out, separate domains), a cross-site cookie (rejected).
- **2026-11-05: login moved from `localStorage` to an HttpOnly cookie.** The author asked for it as the safer option: page scripts (and any XSS) can no longer read the token. Cost: cookies are sent on every request to the API, so non-GET requests need an `X-Requested-With` header (CSRF defence) and the cookie needs `SameSite`/`Secure` settings that depend on how the frontend and API are hosted. The socket gets a short-lived ticket instead.
- **2026-11-05: DeepSeek added as a third provider, models no longer whitelisted.** The author asked for DeepSeek and for the latest OpenAI and Gemini models. DeepSeek reuses the OpenAI SDK with a different `baseURL`. The backend now accepts any well-formed model id (the app offers each provider's live list), and the agent dialog was redone as Identity / Model / Behaviour with a provider picker.
- **2026-11-05: the author did not like The Departure Board** (the committed look) and asked for alternatives. A bolder re-roll gave three: The Score (dance notation), The Lantern Room and a build manual; the author chose the Lantern Room, then asked about Liquid Glass and got a prototype to compare. He then asked about Liquid Glass; after prototypes of both and of a merge, he chose the merge, "Glass Lanterns" (see the next entry).
- **2026-11-05: users bring their own AI keys.** Each user saves their own OpenAI, Gemini and DeepSeek keys in Profile; usage is billed to them. Stored encrypted (AES-256-GCM), never returned, verified with the provider before saving (only a clear 401 rejects). Server `.env` keys are now an optional shared fallback. See [[architecture]].
- **2026-11-05: livelier glass.** The author liked Glass Lanterns but wanted it more like iOS Liquid Glass, with real bending and more animation. Chose `liquid-glass-react` (MIT, React 19) for the refraction and `motion` for the animation. Refraction is used only on the nav and lantern tiles, so cost stays low. Rejected: `liquid-glass-js` (0.1.0, too new, clones the background), `@specy/liquid-glass` (Three.js, 1.9 MB).
- **2026-11-05: Nebula is "Glass Lanterns"**: Liquid Glass material with the Lantern Room's meaning. A glass tile lit from inside is a working agent, a dashed outline an idle one; one vermilion seal is the only accent; dense screens use calm `Panel` surfaces and glass is only chrome. Recorded in `frontend/DESIGN.md`. Refraction was left out (Chromium only). See [[architecture]].
- **2026-11-03 (superseded 2026-11-05): Nebula gets its own look, not NotionCraft's.** "The Departure Board" (split-flap sign), chosen by the author from a dealt hand over a switchboard "Patch Bay". It shows what the product is for: live numbers per agent. Recorded in `frontend/DESIGN.md`. See [[architecture]].
- **2026-11-03 (superseded): amber is only a marker.** The header band and the single active row or route. Never a button or link colour. Red is for errors only (inferred: keeps the board readable).
- **2026-11-03: landing copy describes the product, not an agency.** The old copy (services, five-step process, subscription) was a leftover template and untrue.
- **2026-11-03: sample numbers are labelled** and use the app's real model ids. No customer or performance claims exist.
- **2026-11-03: API address came from `NEXT_PUBLIC_API_URL`** (default the production Render URL). Replaced on 2026-11-05 by the `/api` proxy (`BACKEND_URL`) plus `NEXT_PUBLIC_DIRECT_API_URL`.
- **Audience:** recruiters and engineers (portfolio piece first). In `frontend/PRODUCT.md`.
- **Database is Neon**, not Supabase. The backend uses the Neon HTTP driver.
- **Work lands on `main`.** Pushes mirror to GitLab.
